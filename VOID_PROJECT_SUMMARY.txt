1. EXECUTIVE SUMMARY & BRAND IDENTITY
================================================================================
VOID is conceived as an independent, brutalist unisex streetwear archive and 
atelier that challenges fast-fashion commercialism and generic SaaS e-commerce 
templates. 

The visual and conceptual identity is rooted in:
- High-fashion campaign editorial photography.
- Asymmetric, art-directed layouts alternating between dark industrial concrete
  surfaces and warm ivory editorial panels.
- Brutalist typography scales with oversized display headlines and technical
  monospaced metadata.
- Fluid unisex proportions based on weight, drop, and silhouette rather than gender.
- A strict "Zero Restocks Protocol" where collections release in limited sequential 
  waves that migrate to the permanent archive once allocation is exhausted.

6. STATE MANAGEMENT & CLIENT ARCHITECTURE
================================================================================
State is managed via modular React Contexts with automatic localStorage persistence:

- CartContext (frontend/src/context/CartContext.tsx):
  * State: items (CartItem[]), isOpen (boolean), totalCount (number), subtotal (number).
  * Methods: addToCart(product, size, color, qty), removeFromCart(id), updateQuantity(id, qty), clearCart(), openCart(), closeCart().
  * Persisted key: 'void_cart_state_v1'

- WishlistContext (frontend/src/context/WishlistContext.tsx):
  * State: items (WishlistItem[]), isOpen (boolean), totalCount (number).
  * Methods: toggleWishlist(product), isInWishlist(id), openWishlist(), closeWishlist().
  * Persisted key: 'void_wishlist_state_v1'

- ToastContext (frontend/src/context/ToastContext.tsx):
  * State: toasts (ToastMessage[]).
  * Methods: addToast(message, type, title, duration), removeToast(id).
  * Types: 'success', 'error', 'info'.

8. BACKEND INTEGRATION SPECIFICATIONS & FUTURE ROADMAP
================================================================================
The project root contains backend/ prepared for Node.js + Express + MongoDB.

RECOMMENDED MONGOOSE SCHEMAS:
1. Product: name, subtitle, sku, slug, category, collection, drop, wave, price,
   originalPrice, description, details, materials, fit, sizes, colors, images,
   badge, inStock, stockCount, isFeatured, isNewDrop, releaseStatus.
2. Collection: title, code, description, season, itemCount, heroImage, thumbnail, slug.
3. Order: customerEmail, shippingAddress, items (productId, size, color, quantity, price),
   subtotal, tax, shipping, total, paymentStatus, stripeSessionId, fulfillmentStatus.
4. Subscriber: email, subscribedAt, isActive.

REST API ENDPOINTS TO IMPLEMENT IN BACKEND:
- GET  /api/products           -> List products with filters, sorting, and pagination
- GET  /api/products/:slug     -> Retrieve specific product by unique slug
- GET  /api/collections        -> Retrieve all active collections
- POST /api/newsletter/subscribe -> Record subscriber email
- POST /api/checkout/create-session -> Initialize Stripe checkout session
- POST /api/webhooks/stripe    -> Process payment success, verify inventory, emit receipt

CONNECTING FRONTEND TO BACKEND:
Create .env in frontend/:
  VITE_API_URL=http://localhost:5000/api
Update productService.ts to route requests through apiClient directly to the API endpoints.
